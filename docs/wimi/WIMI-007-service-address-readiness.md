# WIMI-007 — Повторное использование выбора адреса Taxi

**Статус:** аудит подтвердил существующие механизмы выбора точки и геокодирования в Taxi. Следующий шаг — переиспользовать их в WIMI, не создавать новый geocoder и не включать реальные заказы.  
**Базовая ветка:** `feat/wimi-server-pricing-quote`  
**Зависимости:** WIMI-005, WIMI-006 и PR #9.

## 1. Цель

В WIMI адрес услуги должен подтверждаться выбранной точкой с координатами. Повторно использовать существующие механизмы Taxi для текстовых подсказок, выбора точки на карте и обратного геокодирования. Не включать реальный `create` в рамках этой задачи.

## 2. Результаты аудита

Проверены текущие WIMI-компоненты и существующий код Taxi в `main`:

- `taxi/src/wimi/WimiApp.tsx` содержит обычное текстовое поле `wimi-address`; оно пока не получает координаты и не подтверждает выбранное место.
- `taxi/src/wimi/mockAdapter.ts` хранит адрес как строку. Структурированной модели подтверждённого местоположения нет.
- `taxi/src/components/LocationInput/index.tsx` — существующий ввод точки Taxi. Он получает подсказки через `backendGateway.getPointSuggestions`, выбирает точку из результата и предлагает открыть карту.
- `taxi/src/pages/Passenger/index.tsx` содержит рабочую логику выбора точки по центру карты: `setPointAsMapCenter('from' | 'to')` сохраняет latitude/longitude и вызывает `passengerGateway.reverseGeocode`. Защита `mapPointRequestId` не позволяет старому ответу геокодирования перезаписать более новый выбор.
- `taxi/src/platform/adapters/LegacyPassengerGateway.ts` экспортирует `reverseGeocode` из существующего `backendGateway`.
- `taxi/src/components/Map/index.tsx` уже поддерживает отображение выбранных точек `from` и `to`. Карта связана с Redux и модальным состоянием приложения.
- `taxi/src/wimi/index.tsx` запускает WIMI с `BrowserRouter`, но без Redux `Provider`; `WimiApp` сейчас не подключён к существующему `LocationInput` и модальной карте напрямую.

Следовательно, провайдер геокодирования выбирать заново не требуется. Задача — аккуратно переиспользовать существующие API и поведение выбора точки, учтя Redux-зависимости UI Taxi. Нельзя просто импортировать `LocationInput` или `Map` в WIMI без подготовки нужного store/provider и управления модальным состоянием.

## 3. Обязательные ограничения

1. Использовать существующие `getPointSuggestions` и `reverseGeocode`/адаптеры Taxi, если их контракт подходит WIMI; не создавать параллельный внешний geocoder.
2. Не использовать свободный текст адреса как доказательство наличия координат.
3. При редактировании адреса сбрасывать координаты и подтверждение выбранной точки.
4. Не подменять адрес услуги геолокацией телефона. Текущее местоположение может быть лишь начальным центром карты, но не подтверждённой точкой заказа.
5. Проверять координаты как конечные числа в диапазонах latitude `[-90, 90]` и longitude `[-180, 180]`.
6. Сохранять защиту от гонок запросов: ответ старого поиска/геокодирования не должен перезаписывать более новый выбор.
7. Не передавать административные `token/hash` в браузер.
8. Не придумывать поля DTO `POST /drive` и не отправлять реальные заказы.
9. Не менять `main` и не сливать PR автоматически.

## 4. Реализация

1. Сопоставить интерфейсы `IAddressPoint`, `ISuggestion`, `LocationInput`, `getPointSuggestions` и `reverseGeocode` с минимальной моделью WIMI.
2. Реализовать контролируемый выбор адреса для WIMI на базе существующего Taxi-контракта. По возможности вынести независимую логику в общий адаптер; не переносить в WIMI весь Redux-зависимый экран пассажира.
3. Дать пользователю выбрать результат текстовой подсказки или точку на карте. Для выбора на карте сохранять координаты и получать человекочитаемый адрес через существующий reverse geocoder.
4. Показывать состояние загрузки/ошибки; если reverse geocode не ответил, не терять выбранные координаты, но явно отмечать, что адрес не распознан.
5. При изменении адреса аннулировать прежние координаты и подтверждение.
6. Составить mapping-таблицу WIMI draft → подтверждённый DTO платформы только по фактическому backend-коду и тестовому ответу. Не предполагать, что поля количества детей, возраста или комментария поддерживаются сервером.

## 5. Проверки

1. Подсказка сохраняет адрес и координаты выбранного результата.
2. Выбор центра карты сохраняет координаты и пытается получить адрес через существующий reverse geocoder.
3. Изменение текста адреса сбрасывает старые координаты и подтверждение.
4. Пустой результат, отказ сети и некорректные координаты не подтверждают местоположение.
5. Отказ reverse geocode не удаляет координаты выбранной точки и не ломает форму.
6. Запоздалый ответ старого запроса не заменяет результат более нового выбора.
7. Другие поля формы сохраняются после ошибки поиска.
8. Реальный `create` не вызывается.
9. Проходят `npm run build:wimi`, `npm run build:taxi`, Jest и Playwright E2E на актуальном SHA.

## 6. Критерии приёмки

- [ ] WIMI использует существующий механизм подсказок/геокодирования Taxi, без нового независимого провайдера.
- [ ] Пользователь может выбрать подтверждённую точку и увидеть её адрес/координаты.
- [ ] Изменение адреса аннулирует старые координаты.
- [ ] Обработаны сетевые ошибки и гонки запросов.
- [ ] Mapping DTO подтверждён фактическим серверным кодом/тестовым окружением.
- [ ] Реальное создание заказов остаётся отключённым.
- [ ] CI проверен на актуальном SHA, результаты указаны в PR.
