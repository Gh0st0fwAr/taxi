# WIMI-007 — Повторное использование выбора адреса Taxi

**Статус:** реализация добавлена в ветку PR #10; ожидается проверка CI. Подключение реального создания заказов по-прежнему отключено.  
**Базовая ветка:** `feat/wimi-server-pricing-quote`  
**Зависимости:** WIMI-005, WIMI-006 и PR #9.

## 1. Цель

Адрес услуги в WIMI должен быть выбран с подтверждёнными координатами. Использовать уже имеющиеся Taxi API подсказок и геокодирования, а не подключать независимого провайдера. Не включать реальный `create`.

## 2. Аудит существующего Taxi-кода

- `taxi/src/components/LocationInput/index.tsx` использует `backendGateway.getPointSuggestions` для подсказок и открывает карту через обработчик `onOpenMap`.
- `taxi/src/pages/Passenger/index.tsx` выбирает точку по центру карты, сохраняет координаты и получает адрес через `passengerGateway.reverseGeocode`. Счётчики запросов предотвращают перезапись более нового выбора старым ответом.
- `taxi/src/API/index.ts` экспортирует `getPointSuggestions`, `geocode` и `reverseGeocode`; подсказки используют настроенные HERE/Nominatim механизмы.
- `taxi/src/components/Map/index.tsx` связан с Redux и состоянием модального окна Taxi, поэтому напрямую подключать весь экран карты к WIMI без инфраструктуры Taxi не следует.

## 3. Реализовано в WIMI

Добавлен `taxi/src/wimi/WimiAddressPicker.tsx`:

1. Подсказки адреса запрашиваются через существующий `getPointSuggestions`.
2. Выбранная подсказка сохраняет адрес и координаты. Если у подсказки координат нет, адрес разрешается через существующий `geocode`.
3. Отдельный выбор точки на карте использует существующие `getTileServerUrl`, `getAttribution` и `reverseGeocode`. Пользователь перемещает карту под центральный маркер и явно подтверждает точку.
4. Геолокация устройства может использоваться только для центрирования карты; она никогда автоматически не становится адресом услуги.
5. Если обратное геокодирование не сработало, выбранные координаты сохраняются, а UI явно предупреждает, что адрес не распознан.
6. При ручном изменении текста адреса координаты сбрасываются. Валидация запрещает продолжить проверку заказа без конечных координат в диапазонах latitude `[-90, 90]` и longitude `[-180, 180]`.
7. Изменение адреса, даты, времени или длительности аннулирует незавершённый запрос цены, чтобы поздний ответ не вернул устаревшую сумму.

Изменены `WimiApp.tsx`, `mockAdapter.ts`, существующие тесты и стили WIMI. Поля количества детей, возраста и комментария остаются демо-данными; они не отправляются на создание реального заказа.

## 4. Обязательные ограничения

1. Не создавать второй независимый geocoder и не передавать административные `token/hash` в браузер.
2. Не использовать свободный текст без координат как выбранную точку.
3. Не подменять место услуги геолокацией телефона.
4. Проверять координаты на конечные числа и допустимые географические диапазоны.
5. Не придумывать DTO `POST /drive` и не отправлять реальные заказы.
6. Не менять `main` и не сливать PR автоматически.
7. Не менять тариф: серверный шаблон остаётся единственным источником цены.

## 5. Проверки

Добавлены/обновлены тесты для:

- обязательных координат и проверки границ latitude/longitude;
- выбора подсказки с координатами;
- сброса координат при редактировании адреса;
- сохранения введённых данных при возврате с экрана проверки;
- блокировки демо-проверки заказа, если адрес не имеет координат.

Для завершения этапа проверить на актуальном SHA:

- `npm run build:wimi`
- `npm run build:taxi`
- Jest
- Playwright E2E

Результаты CI должны быть зафиксированы в PR; до появления результатов нельзя объявлять сборку и тесты успешными.

## 6. Оставшийся блокер перед реальными заказами

WIMI-007 закрывает выбор адреса и координат в UI. Отдельно остаётся подтвердить mapping полей WIMI → backend DTO на основе фактического серверного кода и тестового ответа. Только после этого можно планировать интеграцию реального `create`. В рамках этой задачи реальное создание заказа, назначение няни, платежи и уведомления не включаются.
