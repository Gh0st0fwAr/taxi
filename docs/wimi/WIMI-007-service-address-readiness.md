# WIMI-007 — Адрес услуги и готовность DTO к интеграции

**Статус:** аудит выполнен частично; безопасная реализация выбора адреса заблокирована отсутствием подтверждённого geocoding/resolver-контракта. Реальное создание заказа остаётся выключенным.  
**Базовая ветка:** `feat/wimi-server-pricing-quote`  
**Зависимости:** WIMI-005, WIMI-006 и PR #9.

## 1. Цель

Подготовить WIMI к будущему созданию реальных заказов: адрес услуги должен быть связан с проверенными координатами, а поля формы — с подтверждённым DTO платформы. Не включать реальный `create` в рамках этой задачи.

## 2. Результаты предварительного аудита

Проверены текущие WIMI-компоненты в ветке `feat/wimi-server-pricing-quote`:

- `taxi/src/wimi/WimiApp.tsx` содержит обычное текстовое поле адреса `wimi-address`; оно не получает координаты и не подтверждает выбранное место.
- `taxi/src/wimi/mockAdapter.ts` хранит адрес как строку. Структурированной модели подтверждённого местоположения нет.
- `taxi/src/components/Map/index.tsx` в `main` — большой компонент карты существующих заказов и позиций водителей. Он использует уже имеющиеся координаты и точки заказа; подтверждённого интерфейса поиска адреса для WIMI в нём не обнаружено. Подключать этот компонент к форме без отдельного анализа нельзя.
- `taxi/src/pages/Order/index.tsx` относится к экрану деталей заказа водителя и не является готовым компонентом выбора адреса для формы WIMI.
- В текущем WIMI-коде нет подтверждённого провайдера геокодирования или адаптера, который преобразует введённый адрес в выбранный результат с координатами.

Это означает, что нельзя безопасно реализовать поиск адреса, просто добавив поля latitude/longitude или подставив координаты браузера: геолокация пользователя не обязательно совпадает с местом оказания услуги.

## 3. Обязательные ограничения

1. Не использовать свободный текст адреса как доказательство наличия координат.
2. Не подставлять координаты по умолчанию и не подменять адрес геолокацией устройства.
3. Не подключать внешний геокодер без явного выбора/подтверждения провайдера, правил конфиденциальности, лимитов и допустимого способа вызова.
4. Не передавать административные `token/hash` в браузер.
5. Не придумывать поля DTO `POST /drive` и не отправлять реальные заказы.
6. Не менять `main` и не сливать PR автоматически.

## 4. Следующий технический этап после выбора источника геокодирования

Реализовать адаптер выбора адреса с независимым от UI контрактом. Результат выбора должен включать как минимум:

- отображаемый адрес;
- широту и долготу, полученные от выбранного доверенного источника;
- идентификатор/метаданные результата, если их предоставляет провайдер;
- признак того, что пользователь явно выбрал конкретный результат.

Проверять координаты как конечные числа в диапазонах latitude `[-90, 90]` и longitude `[-180, 180]`. При изменении текстового адреса сбрасывать подтверждённый результат и координаты. Ошибки поиска не должны удалять другие заполненные поля формы.

После этого составить mapping-таблицу WIMI draft → подтверждённый DTO платформы на основе фактического backend-кода и тестового ответа. Не предполагать, что поля количества детей, возраста или комментария поддерживаются сервером, пока это не доказано.

## 5. Проверки

После реализации адаптера обязательны unit/UI-тесты:

1. Выбор результата сохраняет его адрес и координаты.
2. Изменение адреса сбрасывает старые координаты и подтверждение.
3. Пустой результат, отказ сети и некорректные координаты не подтверждают местоположение.
4. Координаты вне допустимых диапазонов отклоняются.
5. Геолокация устройства сама по себе не считается местом услуги.
6. Запоздалый ответ старого поиска не заменяет результат более нового запроса.
7. Все введённые данные сохраняются после ошибки поиска.
8. Реальный `create` не вызывается.
9. Проходят `npm run build:wimi`, `npm run build:taxi`, Jest и Playwright E2E на актуальном SHA.

## 6. Критерии приёмки

- [ ] Подтверждённый источник поиска/геокодирования выбран и документирован.
- [ ] Результат выбора адреса содержит проверенные координаты.
- [ ] Изменение адреса аннулирует старое подтверждение.
- [ ] Mapping DTO подтверждён фактическим серверным кодом/тестовым окружением.
- [ ] Тесты выбора адреса, ошибок и гонок запросов проходят.
- [ ] Реальное создание заказов остаётся отключённым.
- [ ] CI проверен на актуальном SHA, результаты указаны в PR.

## 7. Что сейчас блокирует реализацию

Нужен подтверждённый источник поиска/геокодирования для места услуги. В текущем WIMI такого контракта нет, а найденная карта Taxi предназначена для визуализации существующих заказов и водителей. Поэтому этот коммит фиксирует audit gap и не добавляет фиктивный выбор адреса или недостоверные координаты.

После выбора провайдера можно реализовать UI и тесты отдельным небольшим изменением, не меняя тариф и не включая реальный `create`.
